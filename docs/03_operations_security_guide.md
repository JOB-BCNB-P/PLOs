# คู่มือปฏิบัติการและความปลอดภัย

## หลักการปฏิบัติการ

ระบบออกแบบให้คำตัดสินเกิดจาก **student × PLO × term** และเก็บ `rule_snapshot` กับ `source_score_ids` ไว้กับผลการประเมิน เพื่อให้รายงานย้อนหลังบอกได้ว่าใช้คะแนนใดและกฎใดขณะตัดสิน การเปลี่ยนคะแนน กฎ หรือสิทธิ์จึงต้องทำผ่านผู้มีสิทธิ์และมี audit trail รองรับ

| บทบาท | ดูข้อมูล | แก้ไข/บันทึก | ขอบเขตสำคัญ |
|---|---|---|---|
| `admin` | ทุกข้อมูลตาม RLS | ได้เมื่อ `can_edit=true` | จัดการ role และสิทธิ์ |
| `executive`, `academic_affairs`, `program_chair` | ภาพรวมและหลักสูตร | ตาม `can_edit` | ใช้กำกับคุณภาพและตัดสินใจ |
| `class_advisor` | นักศึกษาที่ได้รับมอบหมาย | ตาม `can_edit` | ใช้ติดตามรายบุคคล |
| `lecturer` | หลักสูตร/รายวิชาที่เกี่ยวข้อง | ตาม `can_edit` และ assignment | บันทึกผลการวัดของรายวิชา |
| `student` | ข้อมูลของตนเอง | ไม่มี | ต้องผูกด้วย `student_access` |

## ข้อมูลส่วนบุคคลและไฟล์หลักฐาน

ตาราง `students` เก็บ `national_id_hash` แบบ SHA-256 เท่านั้น ไม่เก็บเลขบัตรประชาชนตรง ๆ ไฟล์ evidence อยู่ใน private bucket และเข้าถึงผ่าน Storage RLS; Supabase Storage กำหนดให้ uploads ถูกปิดอยู่แล้วจนกว่าจะมี policy อนุญาต [1] ผู้ดูแลต้องรักษา principle of least privilege, ทบทวน `can_edit` ทุกภาคการศึกษา และไม่ดาวน์โหลดข้อมูลส่วนบุคคลเกินวัตถุประสงค์

| ข้อปฏิบัติ | เหตุผลเชิงควบคุม |
|---|---|
| ห้ามใช้ `service_role` ใน frontend | คีย์นี้ข้าม RLS และต้องเก็บเฉพาะ trusted server [1] |
| ห้ามใช้เลขบัตรจริงเป็นรหัสผ่าน | เป็นข้อมูลระบุตัวบุคคล ไม่ใช่ credential ที่เหมาะสม |
| บันทึกเหตุผลเมื่อเปลี่ยนสิทธิ์ | ช่วยให้ audit ตรวจ who/what/when/why ได้ |
| รักษา evidence เป็น private | แฟ้มการประเมินอาจมีข้อมูลการเรียนหรือข้อมูลระบุตัวบุคคล |
| แก้ migration แบบเพิ่มไฟล์ใหม่ | รักษาประวัติ schema ที่ทำซ้ำและตรวจทานได้ |

## คำเตือนจากฐานข้อมูล

ฟังก์ชันช่วยสำหรับ policy และ RPC ใช้ `SECURITY DEFINER` พร้อมตรวจ `auth.uid()` ภายใน เพื่อให้ RLS ประเมินบทบาทและขอบเขตแถวได้อย่างสม่ำเสมอ Supabase security advisor อาจแจ้งเตือนว่าฟังก์ชันเหล่านี้ callable จาก API แม้ตัวฟังก์ชันจะปฏิเสธผู้ใช้ที่ไม่ผ่านเงื่อนไข ผู้ดูแลต้องทบทวนคำเตือนทุกครั้งหลัง migration และไม่ควรเปิด RPC ใหม่โดยไม่มีการตรวจ role/ownership ที่ชัดเจน

## วงรอบการประกันคุณภาพ

หลังสิ้นภาคการศึกษา ให้ตรวจ mapping I/R/M/P ว่าจุด M/P ครบ, ตรวจรายการ Pending, ทวนสอบหลักฐาน, อนุมัติ verification และบันทึก CQI action ผู้ดูแลควร export report ตามสิทธิ์ที่จำเป็นและเก็บผลการรับรองไว้ในระบบแทนการแก้ผลย้อนหลังโดยตรง
